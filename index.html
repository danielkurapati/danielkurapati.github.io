SCREENSHOT / DEMO GIF

The Problem

I was tutoring at a local academy where tracking student hours, assignment submissions, and invoicing was completely manual. It consumed hours of administrative work for the director and left students without a centralized place to view their upcoming classes or securely submit their coursework.

The Goal

I set out to build a custom, multi-tenant session management platform inspired by Google Classroom but tailored specifically for independent academies. The objective was to provide secure, role-based portals where tutors could manage their rosters, students could access their schedules, and admins could automatically generate Google Sheet invoices.

Technical Architecture

The application is built with a React frontend utilizing Tailwind CSS for a modern, flat, Apple-inspired interface. It connects to a Supabase PostgreSQL backend, relying on strict Row Level Security to protect student and tutor data. Node.js backend endpoints handle the complex logic of cloning Google Sheet templates and dynamically writing live financial data via the Google Drive and Sheets APIs.

Multi-Role Auth

Secure access gates intelligently route traffic to dedicated Tutor, Student, and Admin dashboard views.

Automated Invoicing

A backend integration that generates live Google Sheet invoices via API based on logged session data.

Interactive Portals

Student dashboard equipped with Supabase Storage for seamless file uploads and upcoming class tracking.

Hurdles & Triumphs

A major technical hurdle was managing complex React state to swap between overview and student roster views without causing component rendering overlaps or losing data logic. I triumphed over this by engineering a robust "Traffic Cop" state architecture within the main component to handle internal routing flawlessly.

Key Takeaway: Meticulously planning the database schema and user-flow blueprints upfront significantly accelerates front-end development and prevents frustrating structural bugs.
